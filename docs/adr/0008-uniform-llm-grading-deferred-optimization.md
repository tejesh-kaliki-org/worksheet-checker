# Uniform LLM grading for all Question Types; deterministic path deferred

Status: accepted

Every Answer, regardless of Question Type, is graded via the LLM through an Evaluation Attempt — including objective types like `mcq`, `true_false`, and `numeric` where a deterministic (non-LLM) comparison against a stored correct answer would be technically sufficient for scoring. A deterministic path was considered and explicitly not built now, even though the data model would tolerate it: Feedback (see [`CONTEXT.md`](../../CONTEXT.md)) is a core part of Evaluation for every Question Type, not just an accuracy check, and useful feedback ("you likely confused X with Y") requires the same reasoning the LLM already provides for open-ended types. Splitting scoring (deterministic) from feedback generation (LLM) would add a second code path for marginal cost savings today. This is deliberately left as a "brute-force vs. optimized" axis to revisit, not because it's technically hard, but because demonstrating that exact trade-off (uniform LLM grading vs. a cheaper deterministic-plus-LLM-feedback hybrid) is itself a showcase goal of this project. Revisit when either (a) LLM grading cost/latency at objective-type volume becomes a real constraint, or (b) demonstrating the brute-force-vs-optimized comparison becomes an active goal rather than a deferred one.
